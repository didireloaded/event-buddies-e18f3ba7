# **Event Buddies 2.0**

A multi-event platform with practical tools, social experiences, creative interactions and genuinely fun event features.

Now that we've established Event Buddies is for **many different events**, I would take the product in a much bigger direction.

Imagine someone going to a music festival on Friday, a football match on Saturday, a food market on Sunday and a business conference the following week. They should be able to use the same Event Buddies app for all four experiences.

But here's the important part. **Each event should feel different without requiring a completely different app.**

## **1. What I would improve about the overall concept**

I would build Event Buddies around five ideas.

**Discover**

Help people find interesting events, explore what's happening around them and decide where to go.

**Prepare**

Manage tickets, schedules, saved activities, travel plans and the people they're attending with.

**Connect**

Make it genuinely easier to find friends, coordinate groups and meet new people when they choose to.

**Experience**

Make events more interactive with party tools, games, challenges, live participation and creative features.

**Remember**

Give people a personal record of the events, friends, moments and experiences they've enjoyed.

This also means moving away from a permanently festival-specific interface.

Event Buddies should have a universal home with **Explore, My Events, Buddies and Profile**. Once somebody enters an event, they should get an event-specific experience with its own schedule, map, people and activities.

## **2. The modular event system**

I would introduce different event templates. Organisers choose the relevant features rather than every event displaying every possible tool.

| Event type            | Main experience                     | Special activities                          |
| --------------------- | ----------------------------------- | ------------------------------------------- |
| Music festivals       | Lineup, stages, crew, venue map     | Party games, DJ polls, passport             |
| Concerts              | Artists, tickets, seating or zones  | Fan moments, songs, crowd participation     |
| Nightlife and parties | Friends, venue, programme           | Party Screen, group challenges, photo games |
| Sports                | Fixtures, venue, schedules          | Predictions, fan polls, team challenges     |
| Conferences           | Agenda, speakers, exhibitors        | Networking, session Q&A, surveys            |
| Expos and markets     | Exhibitors, vendors, navigation     | Scavenger hunts, digital stamps             |
| Cultural events       | Performances, activities, locations | Cultural quizzes, community experiences     |
| Private events        | Invitations, guests, programme      | Photo albums, group memories                |

The result would be one platform with a shared foundation and optional event modules.

## **4. How I would develop the platform**

**01**

**Foundation**

Fix the current onboarding and offline experience. Convert the existing Sound of Summer implementation into reusable event modules. Build event discovery, profiles, ticket storage and event-specific plans.

**02**

**Social experience**

Add persistent buddy connections, private crews, better QR sharing and a proper group meeting experience. Introduce backend services only for features that genuinely require them.

**03**

**Fun and creative features**

Launch Party Screen, Event Passport, event-branded photo templates and simple games. These should be reusable across different event categories.

**04**

**Organiser platform**

Build event creation, map management, schedule publishing, announcements and permission controls. This makes the attendee app scalable beyond events that you personally configure.

**05**

**Live and connected experiences**

Introduce opt-in live location sharing, live polls, crew messaging and organiser-managed participation once the reliability and moderation systems are ready.

## **One more important idea**

I would make Event Buddies intelligent about **when** features appear.

Before an event, the homepage should focus on tickets, planning and friends. During an event, it should focus on navigation, what's happening, crew coordination and interactive activities. After the event, it should focus on memories, recaps and the next experience.

That makes the app feel relevant without filling every screen with buttons and cards.

**My overall recommendation is to build Event Buddies as an event-discovery platform with a powerful event-specific companion inside it.** Every event gets its own identity, and organisers choose the modules they need. The social and party features then become the reason people enjoy using it, while the practical features give them a reason to rely on it.
